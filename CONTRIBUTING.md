# Como contribuir

As regras oficiais do evento prevalecem sobre este guia.

- Confira o desafio, as regras e os prazos publicados.
- Para mudanças maiores, abra uma issue descrevendo o problema ou a proposta.
- Não inclua dados pessoais, segredos, credenciais, dados de processos reais ou conteúdo interno não autorizado.
- Não envie código, imagens, fontes ou dados de terceiros sem autorização.
- Use branches curtas e commits claros. Descreva nas pull requests o que mudou e como revisar.
- Peça revisão de um responsável antes de integrar mudanças compartilhadas.

Não publique detalhes de vulnerabilidades em issues públicas. Siga o canal privado em [SECURITY.md](SECURITY.md).
